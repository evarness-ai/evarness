# Evarness — decision log

Design decisions, recorded as they're made. The log is part of the product:
every rule the engine enforces should trace to a reasoned entry here.

| # | Decision | Why |
|---|---|---|
| E1 | **The first release is the assurance spine, simulation-only** — canonical traces, invariant contracts, proof bundles, offline verification — not the full platform (real providers, sandboxed real tools, adapters, visual builder all exist on the roadmap as separate releases). | Everything else stacks on the spine: if traces aren't canonical and contracts aren't checkable, no later capability can be *proven*, only demonstrated. Shipping it alone, narrowly, means the project's first public claim is its most defensible one — and each later capability arrives with the machinery to prove itself already in place. |
| E2 | **Ungraduated capabilities refuse, they don't degrade.** A graph naming a real provider (`anthropic:…`, `ollama:…`) gets a `ProviderError` naming the sim alternative; a `mode: real` tool gets a traced governance block (`policy_violation`) with remediation. Both are tested. | A silent fallback to simulation would make the trace lie about what ran — the exact failure mode this project exists to prevent. An honest refusal also documents the roadmap in the error message itself. The node config keeps its `sandbox`/`egress` knobs so graphs written today parse unchanged when real execution arrives; the run refuses before reading them. |
| E3 | **The canonical digest is a portable contract, not an implementation detail.** `c1:sha256:…` over the canonical event stream (wall-clock envelope stripped, byte-stable serialization). Verified: the digest for the same graph+fixture+seed is identical across macOS/Python 3.14 and Linux/Python 3.10, and identical between a development checkout and the installed wheel. Anything that changes canonical output bumps the `c1` version. | Reproducibility claims are only worth something if they survive the machine boundary — a digest that differs across OS or Python version would reduce "reproducible" to "reproducible on my laptop". The versioned prefix makes canonicalization changes explicit and comparable instead of silent breakage. |
| E4 | **Invariant verdicts live outside the event stream.** Checking a run never alters its digest; a bundle with no declared invariants verifies as "nothing asserted", exit-code-visible. | Evidence and judgment must not contaminate each other: if verification wrote into the trace, verifying a run would change its identity. "Nothing asserted" is kept loud because a green checkmark over zero contracts is the most dangerous kind of pass. |
| E5 | **Tests never touch the developer's home.** The suite pins `EVARNESS_DB` to a temp dir and clears every `EVARNESS_*` overlay before the first import; `evarness.store` resolves its data dir at import time, which is why the isolation lives in `conftest.py` rather than a fixture. | A test suite that reads the developer's own overlays is non-deterministic in exactly the way this project tells its users not to be. |

| E6 | **Layered packages before first release: `core/` (domain-agnostic kernel) / `domains/agents/` / `io/` / `cli/`** — with four hard rules: core never imports domains or io; domains contribute via registries and hooks, never core edits; io consumes public surfaces; the CLI is a thin caller. One config-overlay loader in `core.config` replaces the per-module reimplementations; registries gain pip entry-point discovery (`evarness.plugins`); the seams are typed Protocols and the package ships `py.typed`. Restructured while the repo was still private — zero users, so the only cost was our own diff. | The flat namespace this graduated from made the most important boundary in the codebase invisible: the executor/trace/contracts/proof pipeline never needed to know it was about agents. Naming that boundary before anyone depends on the layout means the public API is stable from day one instead of broken at v0.2 — the one mistake an extension-seeking project can't afford. Structure is documented in ARCHITECTURE.md; digest parity was re-verified after every move (a restructure that changes a digest is wrong by definition). |
| E7 | **Evarness is a framework for *governed workflows*; agents are its first domain.** The kernel pipeline (graph + environment + seed → events → digest → verdicts → proof → offline verify) contains no agent concepts; "a blocked run never reaches the model" and "evaluation precedes deployment" are the same kind of temporal contract. A domain contributes node types, an event vocabulary, an environment, and contract libraries — and inherits determinism, tracing, proof, and verification. | This is the adoption bet: node sets are cheap to write, the assurance machinery isn't — so the community extends domains while the kernel stays small and stable (the pydantic-core / langchain-core lesson). It also states the roadmap honestly: ML pipelines, data flows, and regulated processes are future domains of the same kernel, not pivots. The thesis stays a *claim* until a second domain runs end to end in-tree; the honesty ledger in ARCHITECTURE.md tracks that. |
| E8 | **The proof verdict is tri-state: `ok: true / null / false`.** `true` only when every declared claim was actually checked and held; `null` (**PENDING**) when nothing failed but a scenario paused at a human gate — zero invariants evaluated, zero reproductions attempted; `false` on any contract failure, reproduction failure, or nothing declared. `verdict.invariants_pass`/`reproduced` are likewise `null` when nothing was evaluated/attempted. All surfaces move in lockstep: CLI prints `PROOF: PENDING` and exits 1, the HTML badge reads PROOF PENDING, JUnit gets a failing `proof complete` case, SARIF a `proof-pending` warning — and `verify_proof` recomputes the expected verdict through the same `_verdict()` helper, so a bundle claiming `ok: true` over a paused row fails verification as inconsistent. | Found during pre-release self-verification: the previous optimistic verdict flags meant a paused-only bundle reported `ok: true` / PROOF HOLDS / exit 0 with **zero invariants evaluated** — while a graph declaring *no* invariants honestly failed. An assurance tool whose proof can claim HOLDS about nothing-checked fails its own thesis (E4's "a green checkmark over zero contracts is the most dangerous kind of pass" applies with more force, not less, when contracts are declared but unevaluated). PENDING is a third state rather than a failure because pausing is *designed* behavior (D46 lineage: the gate is the feature) — but a pending proof still gates CI, because "not proven yet" and "safe to merge" must never be confused. Deliberately NOT fixed by auto-approving the default scenario: that would bake a synthetic human decision into a bundle whose whole claim is that a human decided. |
| E9 | **The CLI boundary renders the `EvarnessError` family as one-line messages; a refusal that prevents a run from starting is deliberately NOT traced.** `main()` catches `EvarnessError` and prints `error: <message>` (exit 1, codes unchanged); `ProviderError` and the new `ExportFormatError` join the family (both keep their original bases for existing callers). The provider refusal produces no trace — aligned with the lint gate: a run that cannot start records nothing, because there is nothing honest to record about it. Mid-run refusals (a `mode: real` tool) remain traced `policy_violation` events — the run had started, so its trace exists and must say why it stopped. | Found during pre-release self-verification: the real-provider refusal and the unknown-export-format error escaped as raw Python tracebacks — correct exit code and a correct, actionable message buried under a stack trace, on the same CLI whose tool-mode refusal renders cleanly. A traceback says "the tool broke"; these are the tool *working*. Scoping the catch to the family keeps genuine bugs loud: anything outside `EvarnessError` still gets its full stack trace. |

Deliberate pre-1.0 simplifications, documented rather than hidden: stdlib
`sqlite3` (no ORM) for the activity log; `len//4` token approximation (a real
tokenizer would add a heavy dependency for no contract-relevant gain — token
counts inform budgets, they are not part of the determinism contract).
