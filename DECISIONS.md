# Evarness — decision log

Design decisions, recorded as they're made. The log is part of the product:
every rule the engine enforces should trace to a reasoned entry here.

| # | Decision | Why |
|---|---|---|
| E1 | **The first release is the assurance spine, simulation-only** — canonical traces, invariant contracts, proof bundles, offline verification — not the full platform (real providers, sandboxed real tools, adapters, visual builder all exist on the roadmap as separate releases). | Everything else stacks on the spine: if traces aren't canonical and contracts aren't checkable, no later capability can be *proven*, only demonstrated. Shipping it alone, narrowly, means the project's first public claim is its most defensible one — and each later capability arrives with the machinery to prove itself already in place. |
| E2 | **Ungraduated capabilities refuse, they don't degrade.** A graph naming a real provider (`anthropic:…`, `ollama:…`) gets a `ProviderError` naming the sim alternative; a `mode: real` tool gets a traced governance block (`policy_violation`) with remediation. Both are tested. | A silent fallback to simulation would make the trace lie about what ran — the exact failure mode this project exists to prevent. An honest refusal also documents the roadmap in the error message itself. The node config keeps its `sandbox`/`egress` knobs so graphs written today parse unchanged when real execution arrives; the run refuses before reading them. |
| E3 | **The canonical digest is a portable contract, not an implementation detail.** `c1:sha256:…` over the canonical event stream (wall-clock envelope stripped, byte-stable serialization). Verified: the digest for the same graph+fixture+seed is identical across macOS/Python 3.14 and Linux/Python 3.10, and identical between a development checkout and the installed wheel. Anything that changes canonical output bumps the `c1` version. | Reproducibility claims are only worth something if they survive the machine boundary — a digest that differs across OS or Python version would reduce "reproducible" to "reproducible on my laptop". The versioned prefix makes canonicalization changes explicit and comparable instead of silent breakage. |
| E4 | **Invariant verdicts live outside the event stream.** Checking a run never alters its digest; a bundle with no declared invariants verifies as "nothing asserted", exit-code-visible. | Evidence and judgment must not contaminate each other: if verification wrote into the trace, verifying a run would change its identity. "Nothing asserted" is kept loud because a green checkmark over zero contracts is the most dangerous kind of pass. |
| E5 | **Tests never touch the developer's home.** The suite pins `EVARNESS_DB` to a temp dir and clears every `EVARNESS_*` overlay before the first import; `evarness.store` resolves its data dir at import time, which is why the isolation lives in `conftest.py` rather than a fixture. | A test suite that reads the developer's own overlays is non-deterministic in exactly the way this project tells its users not to be. |

| E6 | **Layered packages before first release: `core/` (domain-agnostic kernel) / `domains/agents/` / `io/` / `cli/`** — with four hard rules: core never imports domains or io; domains contribute via registries and hooks, never core edits; io consumes public surfaces; the CLI is a thin caller. One config-overlay loader in `core.config` replaces the per-module reimplementations; registries gain pip entry-point discovery (`evarness.plugins`); the seams are typed Protocols and the package ships `py.typed`. Restructured while the repo was still private — zero users, so the only cost was our own diff. | The flat namespace this graduated from made the most important boundary in the codebase invisible: the executor/trace/contracts/proof pipeline never needed to know it was about agents. Naming that boundary before anyone depends on the layout means the public API is stable from day one instead of broken at v0.2 — the one mistake an extension-seeking project can't afford. Structure is documented in ARCHITECTURE.md; digest parity was re-verified after every move (a restructure that changes a digest is wrong by definition). |
| E7 | **Evarness is a framework for *governed workflows*; agents are its first domain.** The kernel pipeline (graph + environment + seed → events → digest → verdicts → proof → offline verify) contains no agent concepts; "a blocked run never reaches the model" and "evaluation precedes deployment" are the same kind of temporal contract. A domain contributes node types, an event vocabulary, an environment, and contract libraries — and inherits determinism, tracing, proof, and verification. | This is the adoption bet: node sets are cheap to write, the assurance machinery isn't — so the community extends domains while the kernel stays small and stable (the pydantic-core / langchain-core lesson). It also states the roadmap honestly: ML pipelines, data flows, and regulated processes are future domains of the same kernel, not pivots. The thesis stays a *claim* until a second domain runs end to end in-tree; the honesty ledger in ARCHITECTURE.md tracks that. |
| E8 | **The proof verdict is tri-state: `ok: true / null / false`.** `true` only when every declared claim was actually checked and held; `null` (**PENDING**) when nothing failed but a scenario paused at a human gate — zero invariants evaluated, zero reproductions attempted; `false` on any contract failure, reproduction failure, or nothing declared. `verdict.invariants_pass`/`reproduced` are likewise `null` when nothing was evaluated/attempted. All surfaces move in lockstep: CLI prints `PROOF: PENDING` and exits 1, the HTML badge reads PROOF PENDING, JUnit gets a failing `proof complete` case, SARIF a `proof-pending` warning — and `verify_proof` recomputes the expected verdict through the same `_verdict()` helper, so a bundle claiming `ok: true` over a paused row fails verification as inconsistent. | Found during pre-release self-verification: the previous optimistic verdict flags meant a paused-only bundle reported `ok: true` / PROOF HOLDS / exit 0 with **zero invariants evaluated** — while a graph declaring *no* invariants honestly failed. An assurance tool whose proof can claim HOLDS about nothing-checked fails its own thesis (E4's "a green checkmark over zero contracts is the most dangerous kind of pass" applies with more force, not less, when contracts are declared but unevaluated). PENDING is a third state rather than a failure because pausing is *designed* behavior (D46 lineage: the gate is the feature) — but a pending proof still gates CI, because "not proven yet" and "safe to merge" must never be confused. Deliberately NOT fixed by auto-approving the default scenario: that would bake a synthetic human decision into a bundle whose whole claim is that a human decided. |
| E9 | **The CLI boundary renders the `EvarnessError` family as one-line messages; a refusal that prevents a run from starting is deliberately NOT traced.** `main()` catches `EvarnessError` and prints `error: <message>` (exit 1, codes unchanged); `ProviderError` and the new `ExportFormatError` join the family (both keep their original bases for existing callers). The provider refusal produces no trace — aligned with the lint gate: a run that cannot start records nothing, because there is nothing honest to record about it. Mid-run refusals (a `mode: real` tool) remain traced `policy_violation` events — the run had started, so its trace exists and must say why it stopped. | Found during pre-release self-verification: the real-provider refusal and the unknown-export-format error escaped as raw Python tracebacks — correct exit code and a correct, actionable message buried under a stack trace, on the same CLI whose tool-mode refusal renders cleanly. A traceback says "the tool broke"; these are the tool *working*. Scoping the catch to the family keeps genuine bugs loud: anything outside `EvarnessError` still gets its full stack trace. |
| E10 | **Per-run domain state is a namespaced context extension — the kernel constructs nothing domain-shaped.** `RunContext` carries only what the executor itself needs (emitter, rng, provider, input, approvals, scratch, output) plus `ext: {domain_name: state_object}`, populated fresh each run from factories registered via `register_context_extension`. The agents domain moved its four governance fields (classification, egress_mode, tier, tier_locality) into `AgentsRunState`, reached through its own typed accessor (`agents_state(ctx)`). Composition, not inheritance: N domains coexist in one run, each owning its slot, none able to collide with or read another's. Verified digest-neutral: all five reference digests byte-identical before and after. | The honesty ledger had carried these fields as known debt ("namespace when the second domain lands"). Retiring it BEFORE the public flip follows E6's logic: node authors touch `ctx` directly, so its shape is public API from day one — the cheapest moment to fix a surface is before anyone depends on it. Inheritance was rejected because the kernel constructs the context (a subclass would need injection) and because two domains in one graph cannot both be the subclass. Deliberately NOT moved: `approvals` (pausing is kernel control flow) and `totals` — the token/cost vocabulary the kernel emits in terminal events is inside the `c1` digest contract, so renaming it is a `c1`→`c2` canonicalization bump, honestly triggered by the second domain's graduation, not speculatively before it. |

| E11 | **`judge_panel` aggregates independent verdicts under three honesty rules: lens-veto, majority-only-for-skeptics, inquorate-never-passes.** Where `judge_chain` is ordered curation (first halt short-circuits), the panel is one gate over N independent votes with no short-circuit — every member votes and the full vote is traced (`panel_member_verdict` × N, then one `panel_verdict`, emitted before any block). *diverse* mode ANDs distinct judges: lenses are orthogonal failure modes, so every evaluated lens must survive and no quorum outvotes a safety halt. *adversarial* mode seats one judge N times (seat index in its config), each seat trying to refute; the text survives only if the surviving fraction reaches `quorum` — majority-fail-to-kill. A timed-out member fails OPEN and shrinks the denominator, but a panel below `min_evaluated` (floor-clamped to 1) is inquorate and follows `on_fail`. Panels never repair: a `retry` verdict is a failed vote. Ships with `panel-precedes-output` and `panel-quorate` contracts; aggregation defaults live in `judges.yaml`'s `panel:` section under the standard overlay. | The two modes differ because their failure models differ: redundant samples of one question vote, orthogonal checks veto — collapsing them into one rule would either let a majority outvote a safety halt or make adversarial verification meaningless. Inquorate-never-passes is E8 at node scope: a verdict reached by nobody must never read as a pass, so degradation can shrink the panel but never hollow it. Repair was rejected because mutating the text between members breaks the independence the aggregation assumes — repair belongs to the chain, which is sequential on purpose. Evidence-before-enforcement (verdict traced, then blocked) keeps E4's separation: the trace records what the panel concluded even when the conclusion stops the run. |

| E12 | **The UI surface is a render artifact, not an app: `io/render.py` draws graph + run + verdicts as one self-contained HTML file, and the dependency policy is now explicit.** Runtime deps stay at two (pydantic, pyyaml); anything the package ships to a browser is a generated, self-contained artifact — inline SVG/vanilla JS, zero external requests (CSP `default-src 'none'`, enforced by a test that greps the output for external origins), all `<` in the data island emitted as `\u003c` so hostile fixture content renders inert. The artifact embeds the CANONICAL events verbatim (digest recomputable from the file alone), keeps verdicts in a separate pane and data key (E4 at page-layout scope), always carries a not-established footer (paused ⇒ "invariants never evaluated", zero contracts ⇒ "nothing asserted"), and is byte-stable for deterministic runs — pinned by a golden artifact hash. Versioned `r1`, deliberately outside the `c1` contract. Extension: `register_renderer` registry; layout = longest-path layering over the same topological order as the determinism contract, authored positions winning per node; io stays domain-agnostic — node icons/labels arrive as plain data wired in by the CLI. npm-based tooling (a drag-and-drop builder, if it ever graduates) lives in a separate repo, never here. | An assurance tool's most valuable "UI" is portable evidence, and `prove --html` already set the shape: a file you can open anywhere beats an app you must install, and a `package.json` in this repo would contradict the two-dependency story before anyone reads the README. XSS is treated as the threat model (auditors open these files) rather than an afterthought — the `<` rule exists because a plain `</`-escape loses to the script-data double-escape trick. Byte-stability makes the renderer regression-testable the same way digests made runs regression-testable; wall-clock replay was rejected because the trace records order, not duration. |

| E13 | **The proof browser renders a bundle as one page under three rules: the canvas never lies about identity, the page never vouches for itself, and the island IS the bundle.** `render_proof_browser` (io/render.py) draws the E8 tri-state badge, then one viewer per scenario — canvas, per-scenario playhead, reproduction status, invariant verdicts — with the bundle's `not_proven` section rendered verbatim as the footer. A graph is drawn only when `graph_hash` matches the pinned `graph_sha256` (the CLI auto-resolves the bundle's pattern id and hash-checks it; an explicit `--graph` mismatch raises `RenderMismatchError`; no match ⇒ honest omission, never substitution). A signed bundle is labeled "signature NOT checked by this page" — a page must not vouch for its own integrity; that is `verify`'s job. The data island embeds the whole bundle, so extracting its `bundle` key and running `evarness verify` re-checks the proof offline from the HTML file alone (tested, signature path included). `RENDER_VERSION` bumped r1→r2 (viewer scoping went per-section so one page holds many playheads), with the rule tightened: ANY change to rendered bytes bumps the r-version, and the golden pin moves only with the version. | Phase 2 of E12's thesis: if the artifact is the UI, the bundle — the product's central object — deserves the same treatment, and every rule is an existing decision recurring at page scope: hash-gated canvas is subject pinning (a canvas drawn from an unproven graph would be the trace lying about what ran, E2's failure mode in visual form); the not-vouching rule is E4's evidence/judgment separation applied to the page itself; the embedded-bundle rule makes the browser a *carrier* of verifiable evidence rather than a claim about it. The r-version tightening closes a drift found in review: r1's bytes changed (accessibility labels) without a version bump, which would have made "same version, different golden" possible — the pin now travels with the version by rule, not by habit. |

| E14 | **The render artifact adopts the platform design language (r2→r3): dark-only canvas, group-color dots, a dim→glow→done state progression, and port-to-port arrowhead edges.** Node cards are 150×52 — matched to the canvas the packaged patterns' authored positions were written for (r2's 190px cards made adjacent authored nodes physically touch: a strip of boxes, not a graph). Node states are now unmissable: idle nodes render at half opacity until the playhead reaches them, the active node gets an orange glow, done turns green, a blocking node gets a red glow, paused is dashed orange — and the active node's incoming edges light orange (data visibly flowed). Edges are straight port-to-port lines with arrowheads; long same-row edges arc over the nodes between them so fan-out stays readable. The concern-group color table (`GROUP_COLORS`) lives in the agents domain next to `NODE_PRESENTATION`, and `presentation()` now carries `group`/`color` — io/render.py still receives it all as plain data. Light theme dropped: one look, everywhere the artifact travels. | Found by using the artifact, not by tests: functionally correct output that reads as "the nodes never change and they're glued together" fails the artifact's purpose — legibility of governance IS the feature. The state progression rule (dim until reached) exists because border-tint-only states were invisible at a glance; the glow/dim treatment makes "the model node never lit" true even in a static screenshot. Dark-only was chosen over dual themes because the artifact is the product's face and one deliberate look beats two half-maintained ones; `color-scheme: dark` still lets the browser render form controls correctly. Dimensions follow the authoring canvas rather than the other way around because authored positions are data we must not distort (same reason authored positions win in layout). Versioned r3 with the golden pin moved in the same commit — the E13 rule, followed. |
| E15 | **The docs site is generated, checked, and gated — never a second source of truth.** MkDocs Material pinned in a `[docs]` extra (build-time only, never in the wheel — the E12 dependency policy applied to docs tooling). Site pages *include* the canonical markdown from the repo root via a build hook — there is no forked prose; the hook rewrites repo-relative links to site-context targets before MkDocs validates them, and the build runs `--strict` (a broken link fails it). The live-demos page is built BY the product: the hook drives the real CLI (`run --html`, `prove`, `render`) at build time and **fails the docs build if the artifacts' digests drift from the reference values the prose cites** — the site cannot publish a claim the build didn't just demonstrate; the proof browser's raw bundle is published beside it so any visitor can `evarness verify` the docs' own proof offline. Deployment to GitHub Pages is gated on repository visibility (`!github.event.repository.private`): the deploy job skips while private and starts publishing automatically from the first main push after the public flip. | The blog-claim audit that Phase 3 did by hand — checking that every digest the prose cites actually reproduces — becomes permanent and mechanical: docs drift is now a build failure, not a review finding. Demos-as-product-output beats screenshots because a screenshot of an assurance tool asserts nothing, while a published artifact carrying a verifiable bundle lets the reader check the docs' claim without trusting the docs. The visibility gate encodes "build now, deploy at flip" as one line instead of a manual step someone must remember on launch day. Snippet-inclusion over copied pages for the same reason the digest is canonical: two renderings of one source cannot drift; two copies always do. |

| E17 | **The product blog is part of the docs site — same build, same gates, same flip.** Posts live under `docs/blog/posts/` and render through MkDocs Material's built-in blog plugin (no new dependency; the `[docs]` extra is unchanged). A post is subject to everything E15 already enforces: `--strict` link checking, the demos hook's digest gate behind any artifact the post links, and the visibility-gated deploy — posts written while the repo is private simply publish at the flip. First post: "The trace is the UI" (the E12→E14 render arc). | A blog hosted outside the repo would be a second source of truth about the product — the exact drift E15 exists to prevent, applied to announcements instead of docs. Keeping posts inside the gated build means a post's claims are checked by the same machinery as the docs' claims: a post cannot cite a digest the build didn't just reproduce. Announcement posts on other surfaces point here rather than restating. |

Deliberate pre-1.0 simplifications, documented rather than hidden: stdlib
`sqlite3` (no ORM) for the activity log; `len//4` token approximation (a real
tokenizer would add a heavy dependency for no contract-relevant gain — token
counts inform budgets, they are not part of the determinism contract).
